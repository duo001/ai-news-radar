# 数据源与已知坑（抓层最易坏，改动 GitHub 结构时先看这里）

## 三条通路

| 通路 | 有 token | 无 token | 额度 |
|---|---|---|---|
| Search API `api.github.com/search/repositories` | 30 次/分钟 | 10 次/分钟，超限 403/429 | 脚本匿名时限速 8s/条 |
| Repo/Readme API `api.github.com/repos/...` | 5000/小时 | 60/小时 | 超限自动降级网页 |
| 网页 `github.com/<repo>` + `raw.githubusercontent.com` | 不需要 token | 同左 | 零额度，慢（单仓约 15-25s） |

token 发现顺序：环境变量 `GH_TOKEN/GITHUB_TOKEN/GITHUB_PAT` → `config.json.gh_token`
→ `~/.config/gh/hosts.yml` 的 `oauth_token`（只读文件，不执行 `gh auth token`——未登录时该命令会挂起）。

## 已知坑

1. **trending 改版**：repo 链接在 `<h2>` 内且可能被 `data-hydro-click` 包裹，
   解析必须按 `<article class="Box-row">` 切块、只在 h2 里取 `href="/owner/name"`。
   返回 0 条 = 页面结构变了，先 `curl` 一个 article 块核对选择器。
2. **不要执行 `gh auth token` / `git credential fill`**：未登录时会起交互界面挂死子进程，
   参考实现实测卡 25 秒以上。只读配置文件。
3. **匿名 search 限额**：10 次/分钟。类目 query 总数 = 各类目 topic 数 + name 兜底条数，
   当前 3 类目约 25 条，全量 run 匿名约 3-4 分钟。额度耗尽捕获 `RateLimited` 后跳过剩余查询，
   不影响 trending 通路的结果。
4. **分类假阳性——README 徽章/链接**：README 里的 `dosu-ai` 徽章、依赖名、URL 含 `ai` 会让
   短词误命中。准入分类只信任 name/desc/topics（身份字段）；README 全文只用于
   ① 免费/优惠正则信号 ② 模型本体等"否决型"规则（宁可错杀）。
5. **短词必须加词边界**：纯 ASCII 关键词（ai/llm/mcp/rag/gpt）用
   `(?<![a-z0-9])词(?![a-z0-9])`，否则 `ai` 命中 `main/available`，`rag` 命中 `storage`。
   中文词没有单词边界概念，走子串匹配。
6. **泛词不能单独准入**：`model`/`智能`/`机器学习` 这类词太弱（理财 App 也会说 data model），
   放进 `core_keywords.weak`，要求命中两个弱词或一个强词。
7. **`no credit card required` 否定式**：含 `credit card` 子串，必须先判否定式，
   否则同一项目同时出现"需信用卡/无需信用卡"。
8. **raw 路径用 HEAD 别名**：`raw.githubusercontent.com/owner/repo/HEAD/README.md`
   自动跟默认分支；个别仓库 README 文件名大小写不同，候选名列表逐个试。
9. **网页通路星数口径不稳**：页面星数选择器随版本变，拿不到给 0，
   评分热度维度有"无涨速数据"的退化分支，不会崩。
10. **缓存 TTL**：trending 3h、search 6h、repo/readme 24h，在 `gh_client.TTL` 调整；
    `--offline` 完全只读缓存。
11. **匿名 core 额度耗尽的加固**（曾导致深度分析卡死：每仓先重试 3 次再降级，
    叠加 6 个 raw 文件名 ×25s，单仓数分钟）。现机制：① `preflight()` 开跑前查
    `/rate_limit`，剩余 < 候选数+5 即置位进程级 `_core_exhausted`，整轮直接走网页/raw；
    ② 限流响应（403/429 含 rate limit）**立即抛 `RateLimited` 不重试**，并置位降级开关；
    ③ raw 只试 4 个文件名、每个 10s 超时；网页抓取 20s 超时且同仓进程内只抓一次
    （`_scrape_memo`，repo_detail 与 readme 共用）。改这里时注意别把这三条保护拆掉。
12. **网页星数选择器多代结构**：`_scrape_stars()` 按 `repo-stars-counter-star` 的
    title/文本 → `aria-label="N users starred"` → 旧版 stargazers 链接顺序匹配，
    全失配返回 0。radar.py 合并详情时空值/0 不覆盖 search/trending 真值——曾因网页给 0
    把 n8n/firecrawl/markitdown 误判"星数<30"淘汰，这条保护不能删。
13. **候选必须分层截断**：全局按星数 top-N 会让老明星挤掉 ai-tech 新项目（曾致该 tab
    为 0）。`_stratified_select` 按搜索阶段记录的 `cat_hints` 给每类目保底名额。
    新增类目后若发现它的 tab 长期为空，先查这里的配额而不是调分类词。
14. **协议词/协议标签不等于 AI 身份**（registry.py `_PROTOCOL_WORDS` / `_CORE_AI_TOPICS`）：
    mcp、rag、a2a、computer-use、multimodal、model-context-protocol 这类是通用协议/技术，
    非 AI 应用也会接一个——健身 App（openGym，19 个 topic 仅 1 个 mcp）、视频编辑器
    （Concat，单挂 model-context-protocol）都曾因此误报。规则：协议词/协议标签单独出现
    不准入，必须再有 AI 身份词（ai/llm/agent/gpt/大模型/智能体…）或核心 AI topic 佐证；
    核心 AI topic（ai/llm/ai-agent/generative-ai…）单个即可。改 `_PROTOCOL_WORDS` 时
    同步跑 selftest 的 openGym/Concat 回归用例。
15. **topic 名不得冒充关键词（两通道必须分开）**：分类文本 blob 只拼 name/desc，
    topics 走独立的 `topic_blob` 交集通道。早期把 topics 拼进文本 blob，导致 dify、
    JavaGuide 仅因挂了一个叫 `skills` 的 topic 就被生态类强词 `skill` 误准入（词边界
    对 `skills` 同样成立）。同理单挂 `claude-code` topic 的通用 Bot（OpenMausBot/cindy）
    靠严格模式 `strict_topic_match` 挡下：单 topic 时只认本类目专属强词。回归用例在
    selftest [11]（dify/JavaGuide/OpenMausBot）。
16. **生态类目不要放通用 topic**：`mcp`/`ai-agent`/`mcp-server` 非生态项目也会挂，
    放进 agent-skills 曾让它吞掉 29/36 个入选项目、ai-tech tab 归零。生态类只保留
    专属标签（agent-skills/claude-code/claude-code-plugin/cursor-rules/
    deepseek-harness/dsh-plugin），通用 MCP server 归类目 1 发现。
17. **HTML 报告是零 JS 单文件**：内联 CSS、无外部资源（selftest 断言
    `src=/@import/url(http)` 为 0），深浅色靠 `prefers-color-scheme`。改 html_report.py
    后用标准库 `html.parser` 校验标签闭合（见 selftest [11]），所有动态文本必须过
    `html.escape`（有 `<b>&` 转义回归）。
18. **RSS/Atom 可能被强制 gzip，urllib 不自动解压**：deepmind.google 无视请求头
    返回 gzip，`resp.read().decode(errors="replace")` 会产生大量 `ef bf bd`（UTF-8
    替换符），随后 ElementTree 报 `not well-formed: line 1, column 0`。feeds.py 的
    `_decode_body(raw, encoding)` 先按 `Content-Encoding` 头、再按魔数 `b"\x1f\x8b"`
    判断并用 `gzip.decompress` 解压（deflate 走 zlib）；请求头显式带
    `Accept-Encoding: gzip, deflate`。缓存统一存**解压后**的 XML 文本，离线路径
    不再处理压缩。回归见 selftest [12]（按头 / 按魔数两条解压路径）。
19. **资讯采集必须单源容错 + 缓存回退**：`fetch_all` 对每个信源独立 try，一个源挂
    只记进 `news_failures` 不影响其余源；`fetch_one` 网络失败回退本地缓存（过期也用，
    保证离线可出报告），两者都没有才抛 `FeedError`。信源启用/停用是数据配置而非代码：
    `data/sources/feeds.json` 的 `enabled:false` + `disabled_reason`（当前 4 个超时源
    Google Research/HuggingFace/Mistral/Import AI 被停用，网络恢复改 true 即可）。
    `radar doctor` 体检启用数、缓存数和重复 id，不发网络请求。只接零 key 的 rss/atom，
    AIHOT 的 x_search/mp_account 等付费类型明确不做。
20. **feed 摘要会夹带页面 `<style>/<script>`，去标签不等于去噪声**：GitHub Blog 的
    feed 把字体版权 `/* Copyright ... Mona Sans */`、MS Research 把
    `.yt-consent-placeholder{...}` 样式塞进 summary，单纯 `re.sub("<[^>]+>","")` 只删
    标签名，CSS 文本会原样留下。feeds.py `_strip_html` 的顺序是：先 `_BLOCK_RE`
    （DOTALL）整块移除 style/script → 去 HTML 注释 `<!-- -->` → 去普通标签 →
    去残留 CSS 块注释 `/* */` → 仅当文本同时含 `{` 与 `;`/`:` 时才清 `选择器{声明}`
    规则（最后这个守卫防止误伤正文里合法的 `{name}` 占位符和代码片段，实测 AWS 文章的
    `modelSource: {...}` 配置必须保留）。回归见 selftest [12] 噪声清除 + 花括号不误伤。
21. **资讯并发与翻译库 key 设计（v0.6 主力化）**：
    - 并发：`fetch_all(..., workers=8)` 用 ThreadPoolExecutor，各源只写自己的缓存文件、
      无共享可变状态，结果按下标占位保序；`workers=1` 退回串行，selftest [13] 断言两种
      模式离线抓到的 link 集合完全一致。14 源在线实测并发约 20s（≈最慢单源耗时），
      串行是各源之和。
    - 翻译：资讯与仓库是两条独立翻译通道。仓库按 `owner/repo` 存 `translations.json`，
      资讯按文章 `link` 存 `news_translations.json`（同一标题可能跨源重复、链接才唯一），
      待译清单 `todo_news_translate.json`。`build_news_todo` 跳过标题含中文或库中已有的
      条目，`apply_news_todo` 空 zh_title 跳过、已存在不覆盖，`news_coverage` 按标题
      是否含 CJK 统计已译/待译/原生中文。CLI 用 `translate --news` 走资讯通道，不带
      `--news` 仍是仓库通道。回归见 selftest [13]。
    - 注意 `_rerender_news` 只重渲染 md/html、不回写 json 内嵌的 `news_translations`；
      固化 sample 时若先采集后翻译，需要手动把最新翻译库写回 sample-news.json（本次
      交付即遇到：复制到的是翻译前批次，已用翻译库重新渲染并补内嵌字段）。
22. **工作台插件桥接（v0.7，../ai-news-panel）**：引擎被 DSH 插件 `@local/ai-news-panel`
    以 subprocess 方式复用。插件通过 `python3 radar.py news --quiet --json-out <固定路径>`
    调引擎：`--quiet`（news 子命令新增）同时关掉分组摘要打印、feeds 逐源 ✓ 日志和
    时间戳三件套（news-*.json/md/html），只产出 `--json-out` 指定的 JSON，避免插件每
    刷新一次就往 data/ 堆时间戳文件；插件侧固定文件是 `data/plugin-news.json`。
    关键平台事实：持久化 ESM bundle 的 Client 半可用浏览器全局 `fetch`（官方
    hmr/file-actions 包同理），但**没有**动态沙箱插件的 `host.call`；故数据桥走
    Host 半 webServer 注册 `/ai-news/*` 前缀路由 + Client 同源 fetch，而不是 Typert
    remote（@local 包无法自建 @Remote 服务）。信源维护就是插件用 fs 直接改本文件
    （data/sources/feeds.json），引擎与插件共享同一份。
23. **评论 feed 与无效声明的过滤（v0.8 自动发现）**：解析网页 `<link rel=alternate>` 时，
    WordPress 类站点常暴露 `/comments/feed/`、`/replies`、`comment-page-…`，这些是评论
    订阅流不是正文源，混进队列会污染报告（实测 The Decoder 首页即命中）。`discover.py`
    用 `_COMMENT_FEED_RE` + `_is_comment_feed()` 在**两处**过滤：解析 link 标签时（早期
    只在入队时过滤，selftest 立刻抓到漏网），以及 OPML/远程清单入队前。改这条正则要
    同步跑 selftest [14] 的「只留有效 RSS 链接」断言。另外 OPML 里 `<outline>` 没有
    `xmlUrl` 的（纯分组文件夹）必须跳过，否则会拿空 URL 去验证。
24. **外部 OPML 目录的三处坑**：①`plenaryapp/awesome-rss-feeds` 的默认分支是
    **master**（不是 main），opml 路径里 `Tech.opml` 等还带空格，必须
    `urllib.parse.quote` 后拼 URL，否则 404；②`fuxiaoai/tidings-rss` 是 CC0 的分主题
    OPML 仓库（`opml/tidings-ai.opml` 实测 99 条），`JackyST0/awesome-rsshub-routes`
    根目录 `feeds.opml` 实测 105 条——两者都是零开发成本可直连的目录，已固化进
    `data/sources/opml-catalog.json`；③同名「FeedKit」GitHub 仓库是 Swift 库/游戏工具，
    其「444 精选源」是闭源 App 内置目录、无开放下载，**不要试图爬**。
    目录别名表加新条目只改 JSON，`--opml-catalog` 未知别名会报错并列出全部可用别名。
