# 数据源与已知坑（抓层最易坏，改动 GitHub 结构时先看这里）

## 三条通路

| 通路 | 有 token | 无 token | 额度 |
|---|---|---|---|
| Search API `api.github.com/search/repositories` | 30 次/分钟 | 10 次/分钟，超限 403/429 | 脚本匿名时限速 8s/条 |
| Repo/Readme API `api.github.com/repos/...` | 5000/小时 | 60/小时 | 超限自动降级网页 |
| 网页 `github.com/<repo>` + `raw.githubusercontent.com` | 不需要 token | 同左 | 零额度，慢（单仓约 15-25s） |

token 发现顺序：环境变量 `GH_TOKEN/GITHUB_TOKEN/GITHUB_PAT` → `config.json.gh_token`
→ `~/.config/gh/hosts.yml` 的 `oauth_token`（只读文件，不执行 `gh auth token`——未登录时该命令会挂起）。

## 已知坑

1. **trending 改版**：repo 链接在 `<h2>` 内且可能被 `data-hydro-click` 包裹，
   解析必须按 `<article class="Box-row">` 切块、只在 h2 里取 `href="/owner/name"`。
   返回 0 条 = 页面结构变了，先 `curl` 一个 article 块核对选择器。
2. **不要执行 `gh auth token` / `git credential fill`**：未登录时会起交互界面挂死子进程，
   参考实现实测卡 25 秒以上。只读配置文件。
3. **匿名 search 限额**：10 次/分钟。类目 query 总数 = 各类目 topic 数 + name 兜底条数，
   当前 3 类目约 25 条，全量 run 匿名约 3-4 分钟。额度耗尽捕获 `RateLimited` 后跳过剩余查询，
   不影响 trending 通路的结果。
4. **分类假阳性——README 徽章/链接**：README 里的 `dosu-ai` 徽章、依赖名、URL 含 `ai` 会让
   短词误命中。准入分类只信任 name/desc/topics（身份字段）；README 全文只用于
   ① 免费/优惠正则信号 ② 模型本体等"否决型"规则（宁可错杀）。
5. **短词必须加词边界**：纯 ASCII 关键词（ai/llm/mcp/rag/gpt）用
   `(?<![a-z0-9])词(?![a-z0-9])`，否则 `ai` 命中 `main/available`，`rag` 命中 `storage`。
   中文词没有单词边界概念，走子串匹配。
6. **泛词不能单独准入**：`model`/`智能`/`机器学习` 这类词太弱（理财 App 也会说 data model），
   放进 `core_keywords.weak`，要求命中两个弱词或一个强词。
7. **`no credit card required` 否定式**：含 `credit card` 子串，必须先判否定式，
   否则同一项目同时出现"需信用卡/无需信用卡"。
8. **raw 路径用 HEAD 别名**：`raw.githubusercontent.com/owner/repo/HEAD/README.md`
   自动跟默认分支；个别仓库 README 文件名大小写不同，候选名列表逐个试。
9. **网页通路星数口径不稳**：页面星数选择器随版本变，拿不到给 0，
   评分热度维度有"无涨速数据"的退化分支，不会崩。
10. **缓存 TTL**：trending 3h、search 6h、repo/readme 24h，在 `gh_client.TTL` 调整；
    `--offline` 完全只读缓存。
11. **匿名 core 额度耗尽的加固**（曾导致深度分析卡死：每仓先重试 3 次再降级，
    叠加 6 个 raw 文件名 ×25s，单仓数分钟）。现机制：① `preflight()` 开跑前查
    `/rate_limit`，剩余 < 候选数+5 即置位进程级 `_core_exhausted`，整轮直接走网页/raw；
    ② 限流响应（403/429 含 rate limit）**立即抛 `RateLimited` 不重试**，并置位降级开关；
    ③ raw 只试 4 个文件名、每个 10s 超时；网页抓取 20s 超时且同仓进程内只抓一次
    （`_scrape_memo`，repo_detail 与 readme 共用）。改这里时注意别把这三条保护拆掉。
12. **网页星数选择器多代结构**：`_scrape_stars()` 按 `repo-stars-counter-star` 的
    title/文本 → `aria-label="N users starred"` → 旧版 stargazers 链接顺序匹配，
    全失配返回 0。radar.py 合并详情时空值/0 不覆盖 search/trending 真值——曾因网页给 0
    把 n8n/firecrawl/markitdown 误判"星数<30"淘汰，这条保护不能删。
13. **候选必须分层截断**：全局按星数 top-N 会让老明星挤掉 ai-tech 新项目（曾致该 tab
    为 0）。`_stratified_select` 按搜索阶段记录的 `cat_hints` 给每类目保底名额。
    新增类目后若发现它的 tab 长期为空，先查这里的配额而不是调分类词。
14. **协议词/协议标签不等于 AI 身份**（registry.py `_PROTOCOL_WORDS` / `_CORE_AI_TOPICS`）：
    mcp、rag、a2a、computer-use、multimodal、model-context-protocol 这类是通用协议/技术，
    非 AI 应用也会接一个——健身 App（openGym，19 个 topic 仅 1 个 mcp）、视频编辑器
    （Concat，单挂 model-context-protocol）都曾因此误报。规则：协议词/协议标签单独出现
    不准入，必须再有 AI 身份词（ai/llm/agent/gpt/大模型/智能体…）或核心 AI topic 佐证；
    核心 AI topic（ai/llm/ai-agent/generative-ai…）单个即可。改 `_PROTOCOL_WORDS` 时
    同步跑 selftest 的 openGym/Concat 回归用例。
15. **topic 名不得冒充关键词（两通道必须分开）**：分类文本 blob 只拼 name/desc，
    topics 走独立的 `topic_blob` 交集通道。早期把 topics 拼进文本 blob，导致 dify、
    JavaGuide 仅因挂了一个叫 `skills` 的 topic 就被生态类强词 `skill` 误准入（词边界
    对 `skills` 同样成立）。同理单挂 `claude-code` topic 的通用 Bot（OpenMausBot/cindy）
    靠严格模式 `strict_topic_match` 挡下：单 topic 时只认本类目专属强词。回归用例在
    selftest [11]（dify/JavaGuide/OpenMausBot）。
16. **生态类目不要放通用 topic**：`mcp`/`ai-agent`/`mcp-server` 非生态项目也会挂，
    放进 agent-skills 曾让它吞掉 29/36 个入选项目、ai-tech tab 归零。生态类只保留
    专属标签（agent-skills/claude-code/claude-code-plugin/cursor-rules/
    deepseek-harness/dsh-plugin），通用 MCP server 归类目 1 发现。
17. **HTML 报告是零 JS 单文件**：内联 CSS、无外部资源（selftest 断言
    `src=/@import/url(http)` 为 0），深浅色靠 `prefers-color-scheme`。改 html_report.py
    后用标准库 `html.parser` 校验标签闭合（见 selftest [11]），所有动态文本必须过
    `html.escape`（有 `<b>&` 转义回归）。
18. **RSS/Atom 可能被强制 gzip，urllib 不自动解压**：deepmind.google 无视请求头
    返回 gzip，`resp.read().decode(errors="replace")` 会产生大量 `ef bf bd`（UTF-8
    替换符），随后 ElementTree 报 `not well-formed: line 1, column 0`。feeds.py 的
    `_decode_body(raw, encoding)` 先按 `Content-Encoding` 头、再按魔数 `b"\x1f\x8b"`
    判断并用 `gzip.decompress` 解压（deflate 走 zlib）；请求头显式带
    `Accept-Encoding: gzip, deflate`。缓存统一存**解压后**的 XML 文本，离线路径
    不再处理压缩。回归见 selftest [12]（按头 / 按魔数两条解压路径）。
19. **资讯采集必须单源容错 + 缓存回退**：`fetch_all` 对每个信源独立 try，一个源挂
    只记进 `news_failures` 不影响其余源；`fetch_one` 网络失败回退本地缓存（过期也用，
    保证离线可出报告），两者都没有才抛 `FeedError`。信源启用/停用是数据配置而非代码：
    `data/sources/feeds.json` 的 `enabled:false` + `disabled_reason`（当前 4 个超时源
    Google Research/HuggingFace/Mistral/Import AI 被停用，网络恢复改 true 即可）。
    `radar doctor` 体检启用数、缓存数和重复 id，不发网络请求。只接零 key 的 rss/atom，
    AIHOT 的 x_search/mp_account 等付费类型明确不做。
20. **feed 摘要会夹带页面 `<style>/<script>`，去标签不等于去噪声**：GitHub Blog 的
    feed 把字体版权 `/* Copyright ... Mona Sans */`、MS Research 把
    `.yt-consent-placeholder{...}` 样式塞进 summary，单纯 `re.sub("<[^>]+>","")` 只删
    标签名，CSS 文本会原样留下。feeds.py `_strip_html` 的顺序是：先 `_BLOCK_RE`
    （DOTALL）整块移除 style/script → 去 HTML 注释 `<!-- -->` → 去普通标签 →
    去残留 CSS 块注释 `/* */` → 仅当文本同时含 `{` 与 `;`/`:` 时才清 `选择器{声明}`
    规则（最后这个守卫防止误伤正文里合法的 `{name}` 占位符和代码片段，实测 AWS 文章的
    `modelSource: {...}` 配置必须保留）。回归见 selftest [12] 噪声清除 + 花括号不误伤。
21. **资讯并发与翻译库 key 设计（v0.6 主力化）**：
    - 并发：`fetch_all(..., workers=8)` 用 ThreadPoolExecutor，各源只写自己的缓存文件、
      无共享可变状态，结果按下标占位保序；`workers=1` 退回串行，selftest [13] 断言两种
      模式离线抓到的 link 集合完全一致。14 源在线实测并发约 20s（≈最慢单源耗时），
      串行是各源之和。
    - 翻译：资讯与仓库是两条独立翻译通道。仓库按 `owner/repo` 存 `translations.json`，
      资讯按文章 `link` 存 `news_translations.json`（同一标题可能跨源重复、链接才唯一），
      待译清单 `todo_news_translate.json`。`build_news_todo` 跳过标题含中文或库中已有的
      条目，`apply_news_todo` 空 zh_title 跳过、已存在不覆盖，`news_coverage` 按标题
      是否含 CJK 统计已译/待译/原生中文。CLI 用 `translate --news` 走资讯通道，不带
      `--news` 仍是仓库通道。回归见 selftest [13]。
    - 注意 `_rerender_news` 只重渲染 md/html、不回写 json 内嵌的 `news_translations`；
      固化 sample 时若先采集后翻译，需要手动把最新翻译库写回 sample-news.json（本次
      交付即遇到：复制到的是翻译前批次，已用翻译库重新渲染并补内嵌字段）。
22. **工作台插件桥接（v0.7，../ai-news-panel）**：引擎被 DSH 插件 `@local/ai-news-panel`
    以 subprocess 方式复用。插件通过 `python3 radar.py news --quiet --json-out <固定路径>`
    调引擎：`--quiet`（news 子命令新增）同时关掉分组摘要打印、feeds 逐源 ✓ 日志和
    时间戳三件套（news-*.json/md/html），只产出 `--json-out` 指定的 JSON，避免插件每
    刷新一次就往 data/ 堆时间戳文件；插件侧固定文件是 `data/plugin-news.json`。
    关键平台事实：持久化 ESM bundle 的 Client 半可用浏览器全局 `fetch`（官方
    hmr/file-actions 包同理），但**没有**动态沙箱插件的 `host.call`；故数据桥走
    Host 半 webServer 注册 `/ai-news/*` 前缀路由 + Client 同源 fetch，而不是 Typert
    remote（@local 包无法自建 @Remote 服务）。信源维护就是插件用 fs 直接改本文件
    （data/sources/feeds.json），引擎与插件共享同一份。
23. **评论 feed 与无效声明的过滤（v0.8 自动发现）**：解析网页 `<link rel=alternate>` 时，
    WordPress 类站点常暴露 `/comments/feed/`、`/replies`、`comment-page-…`，这些是评论
    订阅流不是正文源，混进队列会污染报告（实测 The Decoder 首页即命中）。`discover.py`
    用 `_COMMENT_FEED_RE` + `_is_comment_feed()` 在**两处**过滤：解析 link 标签时（早期
    只在入队时过滤，selftest 立刻抓到漏网），以及 OPML/远程清单入队前。改这条正则要
    同步跑 selftest [14] 的「只留有效 RSS 链接」断言。另外 OPML 里 `<outline>` 没有
    `xmlUrl` 的（纯分组文件夹）必须跳过，否则会拿空 URL 去验证。
24. **外部 OPML 目录的三处坑**：①`plenaryapp/awesome-rss-feeds` 的默认分支是
    **master**（不是 main），opml 路径里 `Tech.opml` 等还带空格，必须
    `urllib.parse.quote` 后拼 URL，否则 404；②`fuxiaoai/tidings-rss` 是 CC0 的分主题
    OPML 仓库（`opml/tidings-ai.opml` 实测 99 条），`JackyST0/awesome-rsshub-routes`
    根目录 `feeds.opml` 实测 105 条——两者都是零开发成本可直连的目录，已固化进
    `data/sources/opml-catalog.json`；③同名「FeedKit」GitHub 仓库是 Swift 库/游戏工具，
    其「444 精选源」是闭源 App 内置目录、无开放下载，**不要试图爬**。
    目录别名表加新条目只改 JSON，`--opml-catalog` 未知别名会报错并列出全部可用别名。

25. **免费机翻通道（transmart）的三条硬限制**：①**Google 系端点在国内网络不可达**
    （`translate.googleapis.com`/`translate.google.com` 全都超时，`libretranslate.com`
    已改成要 key、Edge 的 `edge.microsoft.com/translate/auth` 已 404 下线），所以
    不要照抄网上「gtx client」教程；可用的是腾讯交互翻译
    `https://transmart.qq.com/api/imt`（POST JSON，`fn=auto_translation`，
    `client_key` 随便编一个 browser-chrome 串即可，实测无鉴权）。②**限制的是字符数
    不是条数**：单批 40 条 × 300 字符 = 12000 字符报 `outOfLimit`，40 条 × 150 = 6000
    通过，所以切片必须**双预算**（`_chunk_texts` 同时卡条数与字符，取 4000 留余量）。
    ③`outOfLimit` 是**限流**不是永久失败，退避 8s 可恢复；用 1.5s 快重试会连环失败。
    另注：并发跑两个采集/翻译进程会互相抢额度，把对方打成 `outOfLimit`——翻译任务
    必须单实例（`setsid nohup` 后确认只有一个 python 进程）。
26. **`runRadar` 成功时不返回 `exitCode`**：插件的 `runRadar(argv)` 在 `handle.done`
    里判 `exitCode === 0` 才 `resolve({stdout, stderr})`，失败走 `reject`。所以调用方
    写 `const r = await runRadar(...); if (r.exitCode !== 0)` 是**恒真**的 bug
    （`undefined !== 0`），会把成功当失败。正确做法：既然 reject 已代表失败，成功
    分支不要再判 exitCode（`/translate` 路由踩过这个坑，表现为 `stderr` 为空却报
    「退出码非 0」）。

27. **改 `feeds.json` 的 `group` 不会自动影响已入库条目**：`news.db` 每行都冗余存了
    `group_name`，所以重分组后旧条目仍显示旧分组。两条路：① 让下一轮在线采集用
    UPSERT 覆盖（`ON CONFLICT(link) DO UPDATE` 会把 `group_name` 一并更新，只覆盖
    还能抓到的条目）；② 直接按 `source_id → group` 做 SQL 更新（
    `UPDATE news SET group_name=? WHERE source_id=?`，707 行秒级完成，历史全在）。
    改完都要跑 `news --offline --quiet --json-out data/plugin-news.json` 重建面板文件，
    否则插件读到的是旧 JSON。分组归类用规则脚本按域名批量映射（不要手改 131 条 JSON），
    归类前先抽查各源前 3 条标题——「听说了吗？」(anymesgs.com) 是 AI 资讯聚合却容易被
    当成个人博客塞进「技术博客」，`joho-todai.com` 是日文科技新闻站不是个人站。

28. **SQLite 报 "unable to open database file" 可能是临时表被沙箱拦截**：DB 文件本身
    可正常 connect/count/普通 select，但带表达式排序 `ORDER BY published IS NULL,
    published DESC` 稳定报错——SQLite 需要建外部排序临时文件（temp_store 默认走磁盘
    /tmp），沙箱禁止时就报这个有误导性的错（看起来像 DB 文件打不开）。修法：连接后
    立即 `PRAGMA temp_store=MEMORY`（db.py `_connect()` 已内置）。LIMIT 很小、不触发
    外部排序时不会暴露，所以单元测试没拦住，数据量涨到近千条才复现。
29. **新增结构化采集器先做网络可达性探测**：freebie-radar 有 10 路采集器，但本环境
    bsky/v2ex/linuxdo/reddit 全部连接超时（public.api.bsky.app IPv6 失败后 IPv4 卡死）。
    落地策略：只实现实测 200 的 openrouter 与 hackernews（Algolia API），其余在
    collectors.json 保留 `enabled:false` + `disabled_reason` 配置位，网络具备后改 true
    并在 `_COLLECTOR_FUNCS` 注册处理函数即可，不写无法验证的死代码。采集器必须与 feeds
    输出同构 entry、共用缓存目录与容错/离线回退，才能无改动汇入同一张 SQLite 表。
30. **deals.json 手工情报与采集结果会重复**：插件把 deals 置顶拼到资讯列表前面，而
    OpenRouter 等采集器可能抓到同链接条目，导致同一卡片出现两次且 deals 缺 enrich
    四字段（form/obtain/topics/codes）。修法：`dealsAsNewsItems` 补齐同构字段
    （form='deal'、obtain='promo'、codes=[]），并用 `mergeDeals()` 按 link 统一去重
    （无链接时退化为 source_id+title 键），三处拼接点（/news 缓存/非缓存、/translate）
    都要走同一个合并函数。

31. **机翻「处理 0 条」但面板仍有英文——翻译选错了数据源**：`translate --news --auto`
    原来只读最新 `news-*.json`，而插件日常走 `news --quiet --json-out plugin-news.json`
    （不产 news-*.json），导致最新 news 文件停在很久以前、不含新资讯，机翻自然无事可做。
    修法：`_news_payload_for_translate()` 比较 plugin-news.json / news-*.json / sample
    的条目数，选**最全的一份**做翻译输入。判断机翻链路是否健康，先对比这两个文件的
    `news.length`，不要只看命令退出码。
32. **扩充分类后短英文词必须加词边界**：把分类从 AI 扩到全领域时，`ev`（电动车）会
    命中 ever/every、`vr` 命中 regular、`ar` 命中 car/start，造成大量误判。统一用
    `_w(pat)` 包成 `(?<![a-z0-9])pat(?![a-z0-9])`（中文走子串不受影响）。另注意
    `_TOPIC_MAX` 从 4 调到 5 后，selftest 的上限断言要引用 `enrich._TOPIC_MAX` 而不是
    写死数字，否则下次再调会误报。验证规则用真实 plugin-news.json 全量跑一遍
    `enrich.attach` 并抽查无标签样本与非 AI 领域（游戏/汽车/金融）各 3 条。

33. **时政/国际类规则必须用三元组、且对泛词收紧**：第一版把 government/president/
    worldwide/全球/国际 等词与普通标签同等对待，结果 958 条资讯里 51 次命中只有 6 次
    在标题、其余全是摘要泛词（war room 商业比喻、Microsoft 365 Went Down Worldwide、
    g7 子串匹配 Crea**g7**…Creator Mode、war 匹配 Warhammer）。修法：
    ① `_TOPIC_RULES` 支持 (name, title_pat, summary_pat) 三元组，摘要命中必须同时在
    标题里找到信号才准入；② war 限定 `war (room|in|on|crimes|zone)` 后又删掉 room，
    最终只保留政军搭配；③ worldwide/全球/国际化 等泛词不单独作为国际信号，要求
    国际关系/贸易/峰会/制裁等词组；④ 模型词 `deepseek` 加负向先行断言，后接
    harness/平台/插件或 URL 字符 `[/\-_]` 时排除（r/deepseek、deepseek-ai/dsh、
    deepseek-creator-mode），真模型新闻由「模型升级/新模型」中文词或独立 deepseek 命中。
    验证方法：全量跑 plugin-news.json，逐条打印命中的具体正则片段（re.findall），
    区分标题命中(T)与摘要命中(s)，先清噪音再补正例。

34. **合法的空 feed 不能被当成采集失败**：arXiv 周末不发布公告，`rss.arxiv.org/rss/cs.AI`
    会返回一个含 `<channel><skip><day>Saturday</day><day>Sunday</day>` 但**零 item** 的
    合法 RSS。原实现「解析不出条目就抛 FeedError」，于是周六、周日、周一早（公告 20:00 UTC
    才出）连续三次失败，触发 `AUTO_DISABLE_FAILS=3` 的自动停用——周一早上 4 个 arXiv 源
    全被停掉，而且健康记录里留了 `auto_disabled=True`。修法：
    ① `parse_feed` 在零条目时检查 XML 根标签，是 `rss`/`feed`/`RDF` 就返回 `[]`（合法空
    feed），否则仍抛 `FeedError`（HTML 错误页、改版页面照旧判失败）；
    ② `fetch_one` 写缓存前判断 `parsed` 非空，空 feed **不要覆盖缓存**，否则离线模式会
    把上一批真实论文条目冲掉。排查同类问题：看 `data/source-health.json` 的
    `consecutive_failures` 与 `last_error`，若错误是「未解析到任何 item/entry」且源是
    周刊/周末停更类，多半就是这条。

35. **论坛类信源的「最新话题」不是资讯流**：奶昔论坛（`forum.naixi.net`）的 RSS 是
    全站最新帖子，20 条里混着「出一张 3HK 储值卡」「voxi 这样是不是就转好 paygo 了」
    「找工作好难」这类二手交易 / 资费问询 / 求职闲聊。它们既不进任何领域标签，也不该
    出现在资讯面板里。治理办法是 `feeds.json` 里给源加 `"noise_filter": "forum"`，
    由 `enrich.noise_reason()` 按四类规则判定后丢弃。两个关键点：
    ① **默认不启用**——正常资讯源里也可能出现「出」「收」等字（「OpenAI 推出…」），
    只有论坛/羊毛类源才标；
    ② **福利帖必须豁免**——同一批帖子里「🇭🇰香港八达通迎新福利」「b站限时领一周大会员」
    「免费 1GB eSIM」是有价值的，规则里用 `_GIVEAWAY_GUARD`（免费/领取/抽奖/迎新/送激活码）
    先判白给信号，交易动词优先级仍高于豁免（「免费 eSIM 转让」照样按交易帖丢）。
    历史入库的噪音要在渲染层再过一次 `_drop_flagged_noise`，并可用一次性脚本从 news 表删除。

36. **已读状态不要写进 SQLite**：面板的已读标记最终放在引擎目录 `data/news-read.json`，
    由插件 JS 侧维护，不进 `news` 表。原因：① deals 条目来自 `deals.json`，压根不在
    news 表里，按 news 建列就永远标不亮它们；② 加列要给已有库跑 ALTER 迁移，而
    「按 link 单独一张小表/小文件」零迁移。若哪天想回到 DB，正确做法是独立表
    `news_read(link PRIMARY KEY, read_at)`，不是给 news 加列。
    前端做乐观更新（先改本地覆盖层、再 POST），失败不回滚——否则网络抖动会让卡片闪回未读。

37. **摘要补译的「已进库就跳过」陷阱**：翻译库按「标题必译、摘要可选」设计，早期
    `build_news_todo` 只要 link 在库里就整体 `continue`，于是「标题译了、摘要没译」的条目
    永远补不上（曾有 30 条长期空缺）。修法是这类条目产出 `only_summary: true` 的任务：
    `auto_translate_news` 只把摘要文本送去翻译，写入时用 `{**prev}` 保留原译文，另记
    `summary_source` / `summary_translated_at`，不覆盖人工精译。
    另一类「缺口」根本不是 bug：Google/Gemini 官方博客的条目本身就不带 summary，
    库里有标题无摘要是正常状态，补译命令会正确报「处理 0 条」。

38. **信源体检的三种死法要分开处理（v0.13 体检）**：① **网络不可达**（Errno 101，
    import-ai/mistral/huggingface/bbc）——本机网络环境问题，源本身活着，保留停用配置，
    换网络环境后改 `enabled:true` 即可恢复；② **反爬挑战/空响应**（anandtech 返回
    stile 验证页、engadget 返回 HTTP 202 空 body、gizmodo 403）——RSS 已不可用，
    直接从 feeds.json 删除并清 DB 旧条目与 source-health 孤儿记录；③ **临时故障已恢复**
    （google-research 重新实测 200/2.5s）——重新启用并把 `consecutive_fails` 清零。
    体检方法：先看 source-health.json 的 last_error/consecutive_fails，再用 urllib 与
    curl 各实测一次（排除瞬时故障），最后 `news --only <id>` 验证解析器真能吃下。
    source-health 里会残留已删源的孤儿键，体检时按配置 id 集合差集清理（本次清 48 个）。

39. **watch 关键词的整词边界与单复数（v0.14）**：英文词用 `(?<![a-z0-9])词(?![a-z0-9])`
    整词匹配，所以配 `agent` 不会命中 `agents`，配 `mcp` 不会命中 `scmcp`。想要复数要在
    watch.json 里同时配 `agent` 和 `agents` 两个词；中文词退化为子串匹配无此问题。
    watch_hits 是渲染层字段、不进 SQLite，改配置后跑一次 `news --offline` 重渲染即可对
    全部历史数据生效，无需迁移。配置文件缺失/损坏时功能静默关闭（返回空列表），不阻断采集。
40. **周报是离线只读命令，不触发采集（v0.14）**：`radar.py weekly` 只从 news.db 读
    近 N 天数据并在内存里跑 enrich.attach + watch.attach_watch，不发任何网络请求，
    因此插件「📰 周报」按钮即使在离线/限流环境也能用；DB 里没有数据时返回退出码 1。
    插件 `POST /ai-news/weekly` 用正则从子进程输出里提取「周报已导出：<路径>」再回读
    Markdown，若改了 radar.py 的这条日志文案要同步改 index.js 的正则。

41. **近似去重只在同语言内做 Jaccard（v0.15）**：跨语言（日文 vs 中文 vs 英文）
    标题词元几乎不相交，强行跨语言比会漏判，但也因此不会误合并——这是有意取舍。
    阈值 0.62、最少 4 个有效词元（停用词剔除后），短标题（"Hi"、版本号 "0.171.0"）
    不参与聚类。主条目选择顺序：来源组优先级（厂商官方>学术>媒体>社区，见
    `_SOURCE_PRIORITY`）→ 发布时间新 → 标题长。dup_of/dup_count 是渲染层字段不入库，
    历史数据重跑 `news --offline` 即可重算。
42. **分组兜底标签只给强领域组（v0.15）**：无标签补全不能靠"有总比没有好"——
    开发者社区/HN/科技媒体是大杂烩，兜底必误判；只有厂商官方、学术研究、AI 媒体、
    安全、硬件与芯片这类身份明确的组才挂兜底标签。规则命中永远优先于兜底，
    兜底只在 `topics_of` 返回空时生效。
43. **watch.json 面板写入后必须重跑离线渲染（v0.15）**：watch_hits 是渲染时算的，
    插件 `POST /watch` 写文件后会自动跑一次 `news --offline --quiet`，否则新关键词
    最长 5 分钟（newsCache TTL）内看不到命中。Python 侧 watch.py 与插件 index.js
    各自实现了一份同构的配置读写，改 JSON 结构时两处要同步。
44. **sourcecheck 的"最近条目"取 30 天全量、"静默"看 7 天窗口（v0.15）**：两个时间
    口径别混——静默判定必须用短窗口（否则所有源都活跃），但显示最近一条要拉长到
    DB 保留期，否则 8 天没更新的源会显示"从未"，误导排查。低频博客（Karpathy、
    Latent Space）长期静默是正常状态，体检命令只报告不自动停用，停用仍需人工确认。

45. **代理要「一套实现」，不能 Node 与 Python 各写一份（v0.17）**：面板「测试连通」
    曾经想用 Node 的 http 模块直连测试，但真正的采集跑在 Python 子进程里，两套代理
    语义（尤其 no_proxy 匹配、https CONNECT 隧道）容易不一致，导致「测通了但采集
    不走代理」的假阳性。现在测试按钮直接调 `netcfg.test_proxy`，与被测对象同源。
    另外标准库不支持 socks，`validate_url` 明确拒绝 socks:// 而不是静默走直连。
46. **术语归一化必须带语境护栏 + 幂等（v0.17）**：无条件把「代理」换成「智能体」
    会毁掉代理服务器/代理人/代理商；无条件把「标记」换成 Token 会毁掉统计意义上的
    标记。规则一律要求原文出现 agent/token/prompt 词根，且组合词先占位再还原。
    同时正则必须排除已归一的输出（`提示(?!…|词)`），否则第二次跑会得到「提示词词」
    ——第一次上线就踩了这个，靠幂等断言兜住。只改 `source=auto:*`，人工精译不动。
47. **备份要能装下"缺失"而不是报错（v0.17）**：精简部署时某些资产本就不存在
    （如没跑过体检就没有 source-health.json），打包逻辑把缺失项写进 manifest 而不是
    抛异常；但全部缺失时必须报错，否则会产出一个只有 manifest 的空备份。
    恢复侧要做 zip-slip 校验（拒绝绝对路径与 `..`），并先写 .tmp 再 replace。
48. **React Hook 不能写在条件 return 之后（v0.18，白屏根因）**：v0.14 加周报时
    `runWeekly = useCallback(...)` 被放在 `if (loading) return …` 之后，loading=true
    时提前返回少调一个 Hook，loading=false 后 Hook 数变多，React 抛
    "Rendered more hooks than during the previous render"，整个面板白屏且无任何
    可见日志。三条防线：① 所有 Hook 一律声明在组件顶部、任何条件 return 之前；
    ② `ErrorBoundary`（getDerivedStateFromError）兜底，渲染崩溃显示重试 UI 而非白屏；
    ③ 前端错误经 `/logs` 落盘 `data/client-errors.log`（JSONL，500 行环形），
    面板「🐞 日志」可查。selftest [21] 用大括号深度跟踪静态扫描 client.js 组件函数，
    顶层 return 之后再出现 Hook 即失败，专门防此回归。
